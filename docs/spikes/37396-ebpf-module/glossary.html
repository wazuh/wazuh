Linux kernel & eBPF

TermMeaningSource
eBPF"extended Berkeley Packet Filter" — kernel VM that runs small, statically-verified sandboxed programs attached to kernel events; the standard way to observe the kernel without writing a kernel module.https://ebpf.io/what-is-ebpf/
BPF programOne compiled eBPF function attached to one hook (kprobe, tracepoint, LSM…). Lives in a .bpf.c file, compiled with clang to BPF bytecode.ebpf.io
VerifierKernel component that statically checks a BPF program is safe (bounded, memory-safe) before allowing it to load.https://docs.kernel.org/bpf/verifier.html
libbpfThe reference C loader library: opens BPF object files, does CO-RE relocations, loads/attaches programs, manages maps.https://github.com/libbpf/libbpf
CO-RE"Compile Once – Run Everywhere": BPF programs reference kernel struct layouts symbolically; libbpf relocates them at load time against the running kernel's BTF, so one binary works across kernel versions.https://docs.kernel.org/bpf/libbpf/libbpf_overview.html
BTFBPF Type Format — compact type metadata describing kernel structs; exposed at /sys/kernel/btf/vmlinux. Prerequisite for CO-RE. Enabled via CONFIG_DEBUG_INFO_BTF (widespread in distro kernels ≳5.x; RHEL 8 backports it to 4.18).https://docs.kernel.org/bpf/btf.html
vmlinux.hHeader generated from a kernel's BTF (via bpftool) giving BPF programs access to all kernel types for CO-RE.libbpf docs
Skeleton (.skel.h)Header generated by bpftool gen skeleton embedding the compiled BPF object and typed accessors; the userspace side #includes it to load/attach.libbpf docs
kprobeDynamic instrumentation hook on (almost) any kernel function entry; oldest, most compatible attach type; function names/signatures are NOT a stable ABI.https://docs.kernel.org/trace/kprobes.html
TracepointStatic, maintained instrumentation point (e.g. sched:sched_process_exec); stable-ish ABI, cheaper than kprobe.https://docs.kernel.org/trace/tracepoints.html
fentry/fexitBTF-based function entry/exit probes (faster, type-safe kprobe successors), kernel ≥5.5 on x86_64.bcc kernel-versions.md
LSM / BPF-LSMLinux Security Module hooks (security_*, e.g. file_open, path_unlink) attachable by BPF since kernel 5.7 — semantically correct security events (see what audit/SELinux see), but require CONFIG_LSM to include bpf (often not default → boot-arg change).https://docs.kernel.org/bpf/prog_lsm.html
Ring buffer / BPF_MAP_TYPE_RINGBUFSingle shared kernel→userspace MPSC event queue with ordering + backpressure signals; kernel ≥5.8. Predecessor: per-CPU perf event array (BPF_MAP_TYPE_PERF_EVENT_ARRAY), works on 4.x but wastes memory and can reorder across CPUs.https://docs.kernel.org/bpf/ringbuf.html
bpf_d_pathBPF helper resolving a struct path to a full pathname; kernel ≥5.10, and only callable from a whitelist of hooks (LSM/fentry) — NOT from kprobes. Central to the LSM-vs-kprobe decision for file events.https://man7.org/linux/man-pages/man7/bpf-helpers.7.html
bpf_get_current_cgroup_idBPF helper returning the current task's cgroup-v2 id (= the cgroupfs inode number); kernel ≥4.18. The main container correlation key. Semantics under cgroup v1 need verification (issue angle 12).bpf-helpers(7)
cgroup v1/v2Kernel resource-control hierarchies containers are placed in. v2 = single unified tree (modern default); v1/hybrid = multiple trees (older distros). Affects what "cgroup id" means.https://docs.kernel.org/admin-guide/cgroup-v2.html
Namespaces (mnt/pid/net)Kernel isolation primitives that define a container; each has an inode number usable as a correlation key.namespaces(7)
CAP_BPF / CAP_PERFMONLinux capabilities (kernel ≥5.8) splitting BPF-load and perf/tracing rights out of CAP_SYS_ADMIN; older kernels need full CAP_SYS_ADMIN.capabilities(7)
CAP_DAC_READ_SEARCHCapability to bypass read/search permission checks — issue lists it for stat-ing overlayfs paths.capabilities(7); Issue (angle 13)
SELinux / AppArmorMandatory-access-control systems (RHEL / Ubuntu-SUSE families respectively) that may deny BPF operations to the agent process; packaging may need policy deltas.Issue (angle 13)
kernel.bpf_stats_enabledsysctl making the kernel account per-program run time — the issue's suggested tool for the p99 runtime measurement.Issue (starting point 11)

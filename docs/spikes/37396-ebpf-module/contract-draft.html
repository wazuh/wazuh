eBPF Module event contract — DRAFT v0 (boundary-neutral core)

Status: draft for review, decides nothing by itself. Written 2026-07-16 as P1.2 of the plan. Reviewers of record: #37533 (FIM), #37534 (IT Hygiene) — acceptance AC-1 — plus #37382 for the correlation-key set (AC-6/O4) and #37532 for the loss/watermark semantics. Items marked [R] are recommendations open to challenge. The contract core is boundary-neutral: it survives whichever way the O5 evaluation lands (component library vs modulesd module vs daemon); the delivery binding is a thin last layer with both variants in §7.

1. Scope and principles

  • What this is: the record format, identity/correlation semantics, subscription and filtering semantics, and reliability semantics for raw runtime events (file, process-exec, network) produced by the eBPF engine for consumer modules.
  • What this is not: no container names, images, pods, labels (engine stays container-blind — INV-3/CON-3: consumers enrich via the Container module #37382); no path→logical-path resolution (#37533 owns it, OOS-1); no rule/policy language.
  • Constraints honored: hand-rolled flat layout, no protobuf (CON/A3.3); consumer-agnostic — subscribing requires zero eBPF-specific code in consumers (CON-2); works with "empty" container context on plain hosts (A7.2, §3.3).
  • Peer patterns adopted: Falco's two-axis versioning (§2.2); Hubble's in-band per-stage loss reporting + Falco's drop-policy hooks (§6); industry-standard filtering split — coarse scope in kernel, fine filters in userspace (§5). evidence/peers.html

2. Record envelope and versioning

2.1 Framing

Every record = fixed 32-byte envelope + fixed per-class body + a trailing string table (variable). All integers host-endian (local delivery only). String fields in bodies are (u16 offset, u16 len) pairs pointing into the string table; absent strings are (0,0). record_len covers the whole record, so a reader can always skip what it doesn't understand — this is what makes append-only schema growth safe.

struct ebpf_rec_hdr {            /* 32 bytes, all records */
    u16 transport_version;       /* framing itself; v0 = 1                  */
    u16 record_type;             /* EVENT=1, LOST=2, SUB_ACK=3, HEALTH=4    */
    u32 record_len;              /* total bytes incl. header + string table */
    u16 event_class;             /* FILE=1, PROCESS=2, NETWORK=3            */
    u16 event_type;              /* per class, §4                           */
    u16 schema_version;          /* per (class); append-only growth         */
    u16 flags;                   /* bit0 STR_TRUNCATED, bit1 CGROUP_V1,
                                    bit2 PATH_CONTEXT_UNPINNED (§4.1)       */
    u64 seq;                     /* per-subscriber monotonic, gap = loss    */
    u64 ts_boot_ns;              /* CLOCK_BOOTTIME at event, kernel-side    */
};

2.2 Versioning [R] — Falco's two-axis model

  • Transport version (envelope + string-table mechanics + control records): bumped only for framing changes; subscriber and engine exchange it at subscribe time and refuse on major mismatch.
  • Schema version per event class: fields are append-only at the END of the fixed body; new fields ⇒ minor bump (old readers skip via record_len); removing or re-typing ⇒ major bump (engine can emit the previous major on request during a deprecation window). Consumers declare the schema versions they understand at subscribe time.

Rationale: engine and consumers may ship independently (issue angle 3); Falco negotiates exactly these two axes at startup (peers §Falco).

3. Identity and correlation keys (feeds O4 / #37382)

3.1 Identity block (every EVENT record)

struct ebpf_identity {           /* 48 bytes fixed + comm strings */
    u32 pid;                     /* tgid (userspace notion of PID)  */
    u32 tid;
    u32 ppid;
    u32 uid, gid;                /* real; effective uid in flags?   */
    u32 _pad;
    u64 proc_start_boot_ns;      /* task start, CLOCK_BOOTTIME      */
    u64 parent_start_boot_ns;
    /* strings: comm, parent_comm, exe_path (best effort)           */
};

[R] Process cookie = (pid, proc_start_boot_ns). PIDs are recycled; the pair is unique per boot and race-free (captured in-kernel at event time). Consumers and the Container module key process-scoped state on the cookie, never the bare PID. Peer precedent: Tetragon's cluster-wide exec_id is the same idea with node identity added — node identity is the agent's concern, not this contract's.

3.2 Correlation block (every EVENT record)

struct ebpf_correlation {        /* 24 bytes */
    u64 cgroup_id;               /* bpf_get_current_cgroup_id(); v2 inode id */
    u32 mntns_ino;               /* task nsproxy inode numbers                */
    u32 pidns_ino;
    u32 netns_ino;
    u32 _pad;
};

[R] Primary key recommendation for #37382 alignment: cgroup_id, with the three namespace inodes as tie-breakers/fallbacks. Rationale: one u64, captured atomically at event time by a stable helper (≥4.18, inside our ≥5.8 floor), equals the cgroupfs inode userspace sees, and the Container module can maintain a cgroup_id→container cache (#37382's stated design). The edge cases #37382 cataloged are the tie-breaker cases: hostPID/hostNetwork pods (pidns/netns = host, cgroup still container-scoped → cgroup_id survives), --cgroupns=host (cgroup path visible differently in-container, id unchanged), Kata/VM runtimes (host-side cgroup of the VMM — keys identify the sandbox, not in-guest detail; documented limitation), pause/sandbox containers (cgroup distinguishes sandbox vs workload containers where the runtime separates them). cgroup v1/hybrid hosts: flag bit CGROUP_V1 set; semantics of the returned id under v1 must be pinned by the P2.2 probe (A12.1) before v0 freezes.

3.3 The host (no-container) path — A7.2 answered

Keys are NEVER empty. On plain hosts every field still populates (root cgroup id, init namespace inodes). At subscribe time the engine sends SUB_ACK carrying the host baseline: the engine process's own cgroup_id and init ns inodes. A consumer distinguishes "host process" from "containerized" by comparing against the baseline — no special cases in the schema, and the same consumer code works on container-free servers.

4. Event classes and schemas (draft field sets)

4.1 FILE (consumer of record: FIM / #37533)

event_typeHook heritageBody fields (beyond identity+correlation)
FILE_OPEN_CREATElsm/file_open ∥ kprobe/vfs_open (in-tree today) u64 inode, u64 dev, u32 open_flags, strings: path, cwd, parent_cwd
FILE_ATTR_CHANGElsm path hooks ∥ kprobe/security_inode_setattr u64 inode, u64 dev, u32 attr_mask (which attrs changed), strings: path
FILE_UNLINKlsm/path_unlink ∥ kprobe/vfs_unlink u64 inode, u64 dev, strings: path
FILE_RENAMElsm/path_rename ∥ kprobe/vfs_rename u64 inode, u64 dev, strings: old_path, new_path
Path semantics — the #37533 question, answered honestly: path is the kernel-resolved path at event time (via bpf_d_path on the LSM set, manual dentry walk on the kprobe set). Whether that string is the in-container view or the host overlay view — and whether the two attach sets agree — is precisely what the P2.2/P2.4 probes measure (SP-8); until pinned, records carry flag PATH_CONTEXT_UNPINNED. The contract guarantees the raw keys either way, so #37533's resolution layer ((container-identity, kernel_path) → (logical, host)) always has its inputs. v0 freeze REQUIRES this flag retired.

5. Subscription and filtering (SD-3 / A4)

subscribe(request) → SUB_ACK | error
request = {
    transport_version, schema_versions[class],
    class_mask,                  /* which classes           */
    type_mask[class],            /* which events per class  */
    scope:  { cgroup_ids[] | ALL },   /* kernel-side, §5.1  */
    exclude:{ self=true, pids[] },    /* kernel-side         */
    path_prefixes[]              /* FILE only; engine-side userspace, §5.2 */
}

5.1 What is enforced IN the kernel [R]

  • Class/type enablement: hooks for unrequested classes are simply not attached (component shape) or detached when no subscriber wants them (module shape) — zero cost for unused classes.
  • Cgroup scoping: a BPF hash map of allowed cgroup ids consulted first thing in every program (IG's mntns_filter pattern; Tetragon's policy scoping). Empty scope = ALL.
  • Self-exclusion: the agent's own pids (engine + consumers) in a deny map — mandatory, prevents feedback loops (FIM watching its own DB writes).

5.2 What stays in userspace

Path-prefix and any per-field filtering (engine-side, per subscriber). Kernel-side string prefix matching is verifier-hostile and peers avoid it too (peers §synthesis c). NOTE the in-tree precedent to kill: today the engine calls FIM's fim_configuration_directory per event (the coupling seam); in this contract the filter is DATA (prefix list) handed over at subscribe, not a callback into consumer code.

Under the module shape, kernel maps hold the UNION of subscriber scopes and per-subscriber refinement happens at fan-out; under the component shape each instance's maps are exact. Same contract, different enforcement point — boundary-neutral.

6. Reliability: ordering, loss, watermark (SD-6 / A6.1 / #37532)

  • Ordering: per-CPU order is preserved; TOTAL order across CPUs is NOT guaranteed. Consumers needing order sort by ts_boot_ns; same trade as all peers.
  • Sequence numbers: seq is per-subscriber and gap-free by construction; any gap a consumer observes equals loss it wasn't told about — defense in depth on top of LOST records.
  • In-band loss reporting [R] (Hubble pattern): 
    LOST record body = {
    u16 stage;        /* KERNEL_RINGBUF=1, ENGINE_QUEUE=2, SUBSCRIBER_QUEUE=3 */
    u16 _pad;
    u32 count;
    u64 first_ts_boot_ns, last_ts_boot_ns;
}
    Emitted on the SAME stream, per subscriber, when drops are detected at any stage; stage taxonomy is per-boundary so tuning is actionable (the Tetragon lesson: metrics alone with opaque stages ⇒ unfixable overflows). Cumulative counters also queryable via HEALTH.
  • Slow-consumer isolation: per-subscriber queues/instances — a slow consumer loses ITS events (gets LOST records saying so) and can never stall the producer or peers (Hubble's structural isolation; Falco's warning about unbounded gRPC queues heeded — queues are BOUNDED, drop-newest, counted).
  • Watermark / enumerate-on-attach — the #37532 answer [R]: SUB_ACK carries {engine_boot_ts, current_seq, host_baseline (§3.3)}. A consumer building a baseline does: subscribe (events start buffering with seq S₀) → scan /proc or disk → reconcile scan against events with seq > S₀. No lost, no double-counted change — the handoff #37532 specifies. Engine-side enumeration ("dump existing tasks per cgroup on attach") is NOT in v0: it drags stateful scanning into the engine and every peer keeps snapshots consumer-side; revisit only if #37532's evaluation shows /proc-walk + watermark insufficient.
  • Degradation signaling: HEALTH records announce attach-set changes (LSM→kprobe fallback at start, class unavailable on this kernel) so consumers KNOW event quality context instead of guessing (feeds D-M4's missing-feature ladder).

7. Delivery bindings (thin layer — both sketched, O5 decides)

7.1 Socket binding (module / daemon shapes)

  • SOCK_SEQPACKET unix socket under queue/sockets/ebpf — preserves record boundaries (one record per packet), connection-oriented (subscriber death = detach), local-only. Handshake = subscribe request record; then EVENT/LOST/HEALTH stream.
  • Records are the flat layout of §2 verbatim — no re-serialization; the engine writes the same bytes it built from the ring buffer.

7.2 Library binding (component shape)

/* C ABI sketch — mirrors the socket verbs 1:1 */
ebpf_engine_t* ebpf_engine_open(const ebpf_engine_cfg*);   /* loads .bpf.o    */
int  ebpf_engine_subscribe(ebpf_engine_t*, const ebpf_sub_request*,
                           ebpf_rec_cb, void* ctx);        /* SUB_ACK via cb  */
int  ebpf_engine_poll(ebpf_engine_t*, int timeout_ms);     /* drives cb       */
void ebpf_engine_close(ebpf_engine_t*);                    /* detach + unload */

The callback receives the SAME record bytes (§2). One subscriber per instance; multi-consumer means multiple instances (per-instance programs/buffers — the kernel facts in questions.html D3). Everything above §7 is identical in both bindings — that is the boundary-neutrality claim, and the in-tree PoC (D4-rev) validates it by A/B-ing both bindings over one record implementation.

9. Open items blocking v0 → v1 freeze

  • cgroup v1/hybrid id semantics (A12.1 probe) — affects §3.2 flag semantics.
  • Path context pinning (SP-8 probe) — retire PATH_CONTEXT_UNPINNED.
  • Exec/net hook selection (P2.2 probes) — §4.2/4.3 hook columns are candidates, not choices.
  • O4 alignment with #37382; O5 outcome folds §7 down to one primary binding.
  • Ring buffer / queue sizing defaults — deferred to D-M4 policy + P2 measurements (current engine: 8 MiB ringbuf, 50k queue default — starting points, not decisions).

The three bands this induces (feature floors per evidence/kernel-features.html)

Band 0 — eBPF impossible. RHEL 7 / CentOS 7 / Oracle 7-RHCK (kernel 3.10; even kprobe BPF programs need 4.1) + all Tier 3. Consequence: FIM keeps audit whodata; process-exec/network eBPF telemetry can never exist here. These are Tier 2 rows the kernel-floor ADR must explicitly exclude (or serve via non-eBPF means, out of scope).

Band 1 — legacy eBPF only. AL2 on 4.14 (also lacks bpf_get_current_cgroup_id, which needs 4.18 → even the primary correlation key is absent!), RHEL/Stream/Alma/Rocky/Oracle 8 (4.18), Debian 10 (4.19), Ubuntu 20.04 GA (5.4). Have: kprobes, tracepoints, cgroup-id helper (≥4.18 only). Missing: BPF-LSM (5.7), ring buffer (5.8), CAP_BPF/CAP_PERFMON (5.8 → needs full CAP_SYS_ADMIN), bpf_d_path (5.10). BTF: RHEL 8 backports it (probe to confirm coverage); Debian 10 / Ubuntu 20.04 GA / AL2-4.14 generally ship without BTF → CO-RE needs external BTF or a non-CO-RE build — a bigger cost than "just add kprobe fallback". Supporting this band = building a perf-event-array delivery path + kprobe-only programs + a BTF strategy + running as CAP_SYS_ADMIN.

Band 2 — full modern eBPF. Everything else, including BOTH Tier 1 Linux entries: AL2023 (6.1/6.12), Ubuntu 26.04 (7.0), RHEL/Stream 9-10 + clones (5.14/6.12), Debian 11-13 (5.10/6.1/6.12), Ubuntu 22.04/24.04 (5.15/6.8, + 20.04-HWE 5.15), AL2 on 5.10/5.15, Fedora, Leap/SLES current SPs / 16. Version-wise: ring buffer, LSM hooks, bpf_d_path, CAP_BPF all present — still gated on distro kernel configs (CONFIG_BPF_LSM, CONFIG_DEBUG_INFO_BTF) and the boot-time lsm= list, which is what the empirical probe matrix must confirm.

What the bands do to the spike's questions

  1. Tier 1 Linux is entirely Band 2. A modern-first design (ringbuf + LSM + d_path, CAP_BPF confinement) covers 100% of Tier 1 with no fallback code at all.
  2. Every hard case is Tier 2, and they split cleanly: Band 0 (exclude — audit keeps FIM alive), Band 1 (the real cost center: perf-array + kprobe + BTF strategy + CAP_SYS_ADMIN), Band 2 (config probes only).
  3. AL2's 5.10 default (since 2026-01) + its upstream EOL (2026-06-30, already past) weaken the case for paying the 4.14 tax; likewise Ubuntu 20.04 GA-vs-HWE matters (HWE 5.15 = Band 2). The kernel-floor ADR (deliverable) should be argued in tier+band terms, not distro anecdotes.
  4. aarch64 is pervasive in Tier 1/2 — and the in-tree audit found a DEAD modern-arm.bpf.c plus an arch-unqualified prebuilt modern.bpf.o shipped from the deps bucket (which is laid out per (os,arch) — see memory project_externals_publish_layout). Open verification item: confirm how/whether today's modern.bpf.o is built for aarch64 (kprobe arg access via PT_REGS is arch-specific).

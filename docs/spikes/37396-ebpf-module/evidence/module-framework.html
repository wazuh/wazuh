Evidence — what "a module" means structurally in the 5.x agent

Source: repo audit on branch main (5.1.0-alpha0), 2026-07-13.

Headline: "module" is not one thing in 5.x. Three coexisting layers: (a) the classic C wmodules framework hosted by wazuh-modulesd (linked list of wm_context, one thread per module); (b) newer C++ engines (Syscollector, SCA, Inventory-Sync, Vulnerability-Scanner) shipped as .so and driven by thin C wm_* wrappers inside that framework; (c) FIM (wazuh-syscheckd) is still its own daemon, not a wmodule. There is no src/modules/ dir.

2. The wmodules framework

  • Interface wm_context — src/wazuh_modules/include/wmodules_def.h:35-43: {name, start, destroy, dump, sync, stop, query}.
  • Modules = singly-linked list of wmodule (wmodules_def.h:47-53); head extern wmodule *wmodules (wmodules.h:84, defined wmodules.c:25).
  • No static registry: appended during config parsing via wm_add() (wmodules.c:160); wm_config() (wmodules.c:97) → ReadConfig(CWMODULE,…) (:120) + always-on modules added unconditionally (:131-153: router, content_manager, inventory_sync, database, control) + default_modules[] factory (:64-73: agent_upgrade; task_manager on manager / agent_info on agent via #ifndef CLIENT).
  • One thread per module: src/wazuh_modules/src/main.c:133-141 walks the list, CreateThreadJoinable(&cur_module->thread, cur_module->context->start, cur_module->data). control module starts first before a startup gate (:119-129).
  • Stop: SIGTERM handler calls each context->stop(data) then pthread_timedjoin_np with a 30 s budget (main.c:280-307).
  • Config dispatch: Read_WModule (src/config/src/wmodules-config.c:30) switches on <wodle name="…">; dedicated readers (e.g. Read_SCA :177) wired to XML elements in src/config/src/config.c:111-219.

3. The 5.x C++ module shape (bridge pattern)

Registered as CMake subprojects building shared libs — src/wazuh_modules/CMakeLists.txt:94-100 (inventory_sync, vulnerability_scanner, sca, syscollector).

Pattern per module: C++ engine class + C ABI shim (extern "C") + thin C wm_* wrapper that fills a wm_context and dlopens the engine:

4. FIM in 5.x

Own daemon (src/syscheckd/src/main.c:67), NOT hosted by modulesd. modulesd can query it over a socket: FIM_NAME "fim" at src/wazuh_modules/include/wmodules.h:42 with comment "It is not a wm:module, but we define the name for query it"; wm_fim_query_json (wmodules.h:237). Structure: syscheck.c, run_check.c, run_realtime.c, syscom.c, file/, registry/, db/, whodata backends whodata/ (audit, Windows) and ebpf/ (see ebpf-engine-audit.html).

5. Event delivery paths (two coexist)

  • Legacy datagram stream: module → wm_sendmsg (wmodules.c:597) → SendMSG → Unix socket queue/sockets/queue (src/shared/include/defs.h:121 DEFAULTQUEUE) → wazuh-agentd (src/client-agent/src/agentd.c:84 StartMQ(DEFAULTQUEUE, READ, 0); src/client-agent/src/event-forward.c:20-49 EventForward() recv→send_msg) → manager (remoted). Syscollector uses wm_sendmsg_ex(… WM_SYS_LOCATION …) (wm_syscollector.c:271).
  • Stateful sync: dbsync deltas → agent_sync_protocol (persistDifference → synchronizeModule, iagent_sync_protocol.hpp:29,53) → manager inventory-sync service.

6. Config end-to-end (Syscollector example)

  1. XML element dispatch: src/config/src/config.c:111-113 → Read_WModule.
  2. Name match: wmodules-config.c:88-90 — strcmp(node->values[0], WM_SYS_CONTEXT.name) → wm_syscollector_read.
  3. Parser builds module: src/config/src/wmodules-syscollector.c:97 — allocates wm_sys_t, sets module->context = &WM_SYS_CONTEXT (~:133), module->data.
  4. Context defines entry: wm_syscollector.c:67-76 (.start = wm_sys_main, …).
  5. modulesd spawns thread on wm_sys_main → dlopen libsyscollector → syscollector_init/start (wm_syscollector.c:645-746).

7. Recipe: adding a NEW module today

  1. Wrapper src/wazuh_modules/src/wm_<name>.c/.h with WM_<NAME>_CONTEXT (pattern wm_syscollector.c:67); sources are glob'd (src/wazuh_modules/CMakeLists.txt:107,112).
  2. Header include block: src/wazuh_modules/include/wmodules.h:61-82.
  3. Config reader: branch in Read_WModule (wmodules-config.c:88+) or dedicated Read_<Name> wired in config.c:111-226.
  4. Always-on (no XML gate): call in wm_config() (wmodules.c:131-145) or default_modules[] (:64-73).
  5. C++ engine: src/wazuh_modules/<name>/ + add_subdirectory at src/wazuh_modules/CMakeLists.txt:94-100; load via so_get_module_handle("<name>").
  6. BPF-object precedent for compiling .bpf.c: src/syscheckd/src/ebpf/CMakeLists.txt + src/external/CMakeLists.txt:1035-1048.

8. ADRs / design docs

  • No ADR convention exists (repo-wide search for adr/decision-record: nothing). #37396's "ADRs committed in the repo" would ESTABLISH the convention.
  • What exists: mdBook under docs/ (docs/book.toml, docs/SUMMARY.md); docs/ref/architecture.md (5.0 Engine replaces analysisd; Unix-socket IPC under queue/sockets/); per-module design docs at docs/ref/modules/<module>/architecture.md (fim, syscollector, sca, inventory-sync; index docs/ref/modules/README.md); docs/dev/ build/run docs. Natural home for the new module's docs: docs/ref/modules/ebpf/ (or a new docs/adr/).

5.x vs older Wazuh (flags for the newcomer)

  • No src/modules/; code split across src/wazuh_modules/, src/shared_modules/, src/syscheckd/. Server-side Engine replaces analysisd.
  • FIM not merged into modulesd; separate daemon + socket query.
  • Big collectors are C++ engines behind C wrappers (5.x shape).
  • Two delivery mechanisms coexist (datagram queue vs dbsync+sync_protocol).
  • eBPF exists in-tree but only as FIM's whodata backend.

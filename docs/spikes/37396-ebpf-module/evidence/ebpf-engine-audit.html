Evidence — the eBPF engine as it exists in-tree today

Source: repo audit on branch main (5.1.0-alpha0), 2026-07-13. Load-bearing citations spot-checked by hand (handle_event filter, SEC() program list, ring buffer map, init/thread seams, CMake gating).

Headline: all eBPF code lives in ONE directory — src/syscheckd/src/ebpf/ — and has ONE consumer: the FIM daemon (wazuh-syscheckd), which uses it as the whodata provider. The engine is fused to FIM (config filtering, event struct, callbacks, install paths). It has NO container awareness (bpf_get_current_cgroup_id unused; zero cgroup hits in the dir) and NO process-exec or network programs — file events only. fanotify: 0 hits anywhere in-tree.

2. External dependencies

  • libbpf via libbpf-bootstrap (bundles libbpf + bpftool): registered packages/externals/external_sources.sh:106, Linux-only flag. Version injected by CI, not pinned in-repo.
  • Skeleton/object generation delegated to libbpf-bootstrap's own CMake: src/external/CMakeLists.txt:1035-1048 (if(IS_LINUX AND IS_AGENT); precompiled modern.bpf.o short-circuit). Engine includes the generated skeleton dir (src/ebpf/CMakeLists.txt:10; ebpf_whodata.cpp:16 #include "modern.skel.h").
  • Nuance: runtime path does NOT use the skeleton — init_bpfobj() loads the raw object: bpf_object__open_file("lib/modern.bpf.o") (ebpf_whodata.cpp:553).
  • CO-RE: yes. modern.bpf.c:11 #include <vmlinux.h>; BPF_CORE_READ throughout; extern int LINUX_KERNEL_VERSION __kconfig; (:98); struct renamedata___local shadow (:108-116) for 5.15 BTF gaps.
  • libelf = build-host requirement (packages/externals/build_external.sh:82); zlib vendored separately; clang needed by libbpf-bootstrap's FindBpfObject.cmake (build_external.sh:78).
  • The .bpf.o ships prebuilt from packages.wazuh.com/deps/ (build_external.sh:541-556); built out-of-repo in a dedicated centos:7+clang-15 image per docs/dev/build-external-dependencies.md:220-231 (issue #28626). DEPS_VERSION = 99-29734 (src/Makefile:404).

4. Kernel features used (verified SEC list)

  • kprobes (4): kprobe/vfs_open :370, kprobe/security_inode_setattr :430, kprobe/vfs_unlink :516, kprobe/vfs_rename :587.
  • LSM (3 hooks × dpath/walk): lsm/file_open :723/:746, lsm/path_unlink :796/:835, lsm/path_rename :914/:949.
  • No fentry, no tracepoints, no perf-event programs. (wrapper_bpf.h tracepoint names = stale.)
  • Maps: BPF_MAP_TYPE_RINGBUF rb, 1<<23 bytes = 8 MiB (:64-67) [verified]; 3× BPF_MAP_TYPE_PERCPU_ARRAY scratch heaps for path reconstruction (:72-95).
  • Helpers: bpf_d_path only in _dpath LSM variants (:734, :807, :935); bpf_probe_read_kernel[_str] pervasive; bpf_ringbuf_reserve :311 / submit :359; bpf_get_current_task :316; bpf_get_current_uid_gid :320; BPF_CORE_READ throughout; PT_REGS_PARM*_CORE for cross-version arg reads (:445-447, :527-529, :614-622).
  • bpf_get_current_cgroup_id NOT used — engine is container-blind today. [verified: zero cgroup hits under src/syscheckd/src/ebpf/]

5. Build & packaging gating

  • Engine only on Linux: src/syscheckd/CMakeLists.txt:125-128 (add_subdirectory("src/ebpf"), link fimebpf). [verified]
  • BPF object only Linux+agent: src/external/CMakeLists.txt:1035.
  • Runtime gates: #ifdef __linux__ + #ifdef ENABLE_AUDIT (main.c:313-320, run_check.c:686-692 [verified]); non-Linux config rejected with msg 6966.
  • Enablement is config, not CMake: <whodata><provider>ebpf|audit</provider></whodata> parsed src/config/src/syscheck-config.c:2070-2080; EBPF_PROVIDER 0 / AUDIT_PROVIDER 1 (syscheck-config.h:104-105), bit-field whodata_provider:1 (:391); default AUDIT (syscheck-config.c:93).
  • Min kernel 5.8 enforced at runtime: ebpf_whodata.cpp:360 (msg 6980).
  • Packaging installs 3 artifacts to ${INSTALLDIR}/lib (+ chcon -t textrel_shlib_t): libfimebpf.so, libbpf.so, modern.bpf.o (src/init/inst-functions.sh:632-656).

6. Fallback story today (two-stage)

  1. eBPF → audit: healthcheck failure at startup flips whodata_provider to audit (syscheck.c:827-831); healthcheck validates kernel ≥5.8, libbpf load, object load, ring buffer creation, and a full create/modify/metadata/delete round-trip (ebpf_whodata.cpp:715-798).
  2. Inside eBPF: LSM programs enabled only if bpf ∈ /sys/kernel/security/lsm (is_bpf_lsm_active() ebpf_whodata.cpp:64-81; selection select_programs() :482-525, msgs 6051/6052); if _dpath variants fail to load (e.g. Amazon Linux 2/2023) it reopens and retries with _walk variants (ebpf_whodata.cpp:552-580, msg 6053).

The audit whodata backend is entirely separate code (src/syscheckd/src/whodata/syscheck_audit.c …).

  • NO container_security/container_instances config or module exists yet.
  • Docker listener wodle (Python): wodles/docker-listener/DockerListener.py; legacy C module src/wazuh_modules/src/wm_docker.{c,h}; docs docs/ref/configuration/wodle-docker.md, docs/ref/modules/integrations/docker.md. Unrelated to the eBPF engine.

Extraction takeaways

  • Physically easy to lift (one dir → one .so) but logically fused at 3 seams: (a) FIM config filtering inside handle_event, (b) FIM's whodata_evt output struct, (c) FIM callbacks + FIM-relative paths.
  • Cleanup candidates found: duplicated file_event struct (kernel/userspace), stale wrapper_bpf.h skeleton, dead modern-arm.bpf.c.
  • The issue's LSM-vs-kprobe question has in-tree prior art ALREADY: both attach paths + runtime selection + dpath/walk retry exist for file events. What does NOT exist: tracepoints, exec & network programs, cgroup/namespace correlation keys, multi-consumer fan-out, any subscription API, perf-event-array fallback (<5.8 unsupported today).

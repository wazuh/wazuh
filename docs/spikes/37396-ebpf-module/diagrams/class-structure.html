The engine's classes and the three data shapes an event passes through

Issue #37396 · class diagram (current code)

Reading order: a kernel event is born as file_event (fixed-size C struct, defined twice — kernel and userspace copies must stay in lockstep), becomes a dynamic_file_event (std::string form) in the bounded queue, and dies as FIM's whodata_evt. The fimebpf singleton holding 9 FIM callbacks is the coupling the spike must cut.

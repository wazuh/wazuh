Where the eBPF engine sits — today vs target

Issue #37396 · context / architecture diagram

Today (main @ 5.1.0-alpha0): the engine is inside FIM

One consumer. The engine filters events using FIM's own directory config, emits FIM's whodata_evt, and is initialized with 9 FIM callbacks. File events only; no cgroup/namespace data collected.

Target (per parent #37203 NFR4, designed by this spike)

The engine becomes the sole producer, consumer-agnostic. Events carry raw correlation keys; consumers enrich by querying the Container module. The engine never depends on the Container module; three sibling spikes consume/review its contract.

# Update: `<agent><manager>` rename implemented

**Decisions**

- No 5.x -> 5.x fallback for `<agent><server>`: it is in no release tag and `v5.0.0-beta4` still shipped `<client><manager>`, so the shape has no installed population.
- `Read_Legacy_Client_Address()` keeps `"server"` and is renamed `xml_client_server`: it reads the 4.x `<client><server><address>`, which this change does not touch.
- `Read_Agent_Server()` -> `Read_Agent_Manager()`, following the precedent set by #38172. The data model (`agent_server`, `logr->server`, `server_count`) keeps its names — it describes the runtime struct, not the tag.
- Manage-Agent candidate XPaths must be a subset of what the parser accepts, so `{agent,server}` was replaced rather than demoted and `{client,manager}` was deleted.

**Delivered**

- Parser: `<agent><manager>` accepted, `<agent><server>` rejected, log and warning text moved with the tag.
- Writers: both shipped templates, `inst-functions.sh`, `register_configure_agent.sh`, `InstallerScripts.vbs`.
- WPK pre-flight: `pkg_installer.sh` and `do_upgrade.ps1` read `<agent><manager>`, keeping the `<client><server>` fallback. Missing either would abort every upgrade on that platform.
- Manage-Agent, migration and reference docs, unit and integration fixtures.

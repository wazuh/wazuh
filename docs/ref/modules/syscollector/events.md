# Events Reference

This document describes the event formats generated by the Syscollector (Inventory) module. Field names follow the Wazuh Common Schema (WCS), an ECS-based schema, so they do not match the raw column names stored in the local DBSync database.

Two authoritative sources define what an event looks like:

- `src/wazuh_modules/syscollector/src/syscollectorTablesDef.hpp`: table columns and primary keys (also documented in [database-schema.md](database-schema.md)).
- The `ecs*Data()` functions in `src/wazuh_modules/syscollector/src/syscollectorImp.cpp`: the column to event field mapping applied before sending.

## Event Structure

All Syscollector events share a common structure:

```json
{
    "collector": "dbsync_network_iface",
    "module": "inventory",
    "data": {
        "event": {
            "changed_fields": [],
            "created": "2026-07-30T09:12:44.154Z",
            "type": "created"
        }
    }
}
```

| Field | Description |
|-------|-------------|
| `collector` | Name of the DBSync table that produced the event, for example `dbsync_hwinfo` |
| `module` | Always `inventory` |
| `data` | Mapped item fields, plus the `event` object |
| `data.event.type` | `created`, `modified` or `deleted` |
| `data.event.created` | Event generation time, ISO 8601 UTC |
| `data.event.changed_fields` | Dotted paths of the fields that changed, only populated for `modified`, which also adds a `previous` object with the old values to each affected top-level object |

## Event Processing

Syscollector events are processed by the Inventory Harvester and stored directly in Wazuh Indexer without going through traditional rule processing, since they represent inventory state rather than security events.

## Integration

Access syscollector inventory data through:

- **Wazuh API**: REST endpoints for querying current inventory state
- **Wazuh Dashboard**: Built-in inventory visualization
- **Direct Database**: Query Wazuh Indexer for raw event data

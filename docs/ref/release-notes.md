# Release notes

## Highlights

- New detection Engine replacing `analysisd`, with a YAML-based ruleset, KVDB lookups, and event enrichment (IOC matching, GeoIP, filters). ([#33493](https://github.com/wazuh/wazuh/issues/33493)) ([#34477](https://github.com/wazuh/wazuh/issues/34477))
- Native event forwarding to the Wazuh Indexer through the `indexer-connector` module; Filebeat is no longer required. ([#33124](https://github.com/wazuh/wazuh/pull/33124))
- Cluster-by-default deployment model: every Wazuh Server installation runs as a cluster node, removing the distinction between clustered and non-clustered deployments. ([#31295](https://github.com/wazuh/wazuh/issues/31295)) ([#27434](https://github.com/wazuh/wazuh/issues/27434))
- Complete Agent/Manager separation: the Agent and Manager are now fully independent products with distinct installation paths, system users (`wazuh` vs. `wazuh-manager`), configuration files, daemon names, and runtime artifacts. Both can be installed and run simultaneously on the same host without conflicts, and all coupling through the reserved agent ID `000` has been removed. This applies to 5.x packages only: Wazuh 4.x agent packages declare a conflict with the `wazuh-manager` package and cannot share a host with a 5.x manager. ([#33378](https://github.com/wazuh/wazuh/issues/33378))
- New stateless event model: agents send lean, self-contained events while the Manager centrally enriches them with agent identity, group membership, and cluster context at the `remoted` boundary, guaranteeing a consistent metadata schema for every event reaching the Indexer and removing `wazuh-db` from the ingestion hot path. ([#33269](https://github.com/wazuh/wazuh/issues/33269))
- New state synchronization model: agents own and persist their module state (FIM, System Inventory, SCA) locally and reconcile it with the Manager through a dedicated synchronization protocol with deterministic versioning and checksum-based recovery, replacing the legacy `rsync` path and reducing network traffic and server-side processing. ([#29533](https://github.com/wazuh/wazuh/issues/29533)) ([#31838](https://github.com/wazuh/wazuh/issues/31838))
- Vulnerability Detection now uses the Wazuh Indexer as the authoritative CVE data source, fed by the CTI service, with CVSS v4.0 support. ([#34919](https://github.com/wazuh/wazuh/issues/34919)) ([#35623](https://github.com/wazuh/wazuh/issues/35623))
- Revamped Role-Based Access Control (RBAC) management, including an upgrade mechanism for existing RBAC configurations. ([#27706](https://github.com/wazuh/wazuh/issues/27706))
- Engine metrics collection, normalization, and indexing pipeline for internal observability. ([#35470](https://github.com/wazuh/wazuh/issues/35470))
- Configurable queue watermarks across manager components (Inventory Sync Server, `indexer-connector`, Engine, Vulnerability Detector, and `remoted`), with graceful overflow handling and saturation warnings, bounding memory use and reducing OOM risk under load. ([#35579](https://github.com/wazuh/wazuh/issues/35579))

## Breaking changes

- No in-place upgrade from 4.x: Wazuh Manager 5.x packages refuse to install on hosts with an existing 4.x (or earlier) installation. A fresh install plus the documented migration process is required. ([#36317](https://github.com/wazuh/wazuh/issues/36317))
- As part of Agent/Manager separation, the installation path moved from `/var/ossec` to `/var/wazuh-manager`; `ossec.conf` → `wazuh-manager.conf`, the XML root `<ossec_config>` → `<wazuh_config>`, `internal_options.conf` → `wazuh-manager-internal-options.conf`, `ossec.log` → `wazuh-manager.log`, the system user/group `wazuh` → `wazuh-manager`, and the control binary and daemons were prefixed accordingly (`wazuh-control` → `wazuh-manager-control`, `wazuh-analysisd` → `wazuh-manager-analysisd`, and so on; the `wazuh-manager.service` systemd unit name is unchanged). Any automation or tooling referencing these paths, filenames, daemon names, or the system user must be updated. ([#33378](https://github.com/wazuh/wazuh/issues/33378)) ([#35479](https://github.com/wazuh/wazuh/issues/35479))
- Filebeat was removed as the log-shipping component; event forwarding configuration moves to the `indexer-connector` block. ([#33124](https://github.com/wazuh/wazuh/pull/33124))
- The cluster is always enabled; the `cluster.disabled` configuration option was removed. ([#31295](https://github.com/wazuh/wazuh/issues/31295)) ([#27434](https://github.com/wazuh/wazuh/issues/27434))
- Deprecated manager daemons were removed: `ossec-authd`, `wazuh-agentlessd`, `wazuh-maild`, `wazuh-dbd` ([#30922](https://github.com/wazuh/wazuh/issues/30922)), and `wazuh-csyslogd`, `wazuh-integratord`, `wazuh-reportd` are no longer shipped ([#30919](https://github.com/wazuh/wazuh/issues/30919)).
- Deprecated CLI tools `manage_agents` and `agent-auth` were removed. ([#30924](https://github.com/wazuh/wazuh/issues/30924))
- `wazuh-authd` no longer replaces an existing agent when a registration names the agent ID explicitly (`POST /agents/insert`). The request is rejected instead: `1708` when the ID belongs to an existing agent, and the new `1763` when the ID's previous owner still has documents pending deletion in the Indexer. Reusing an ID requires deleting the agent and letting its deletion complete. `<force>` is unaffected for enrollments that do not name an ID — those keep replacing by name or IP, and the replacing agent receives a new ID, as before.
- Agent deletion no longer purges the Indexer synchronously: the deletion of the key, the wazuh-db row and the Indexer documents are now decoupled. The Indexer purge becomes a durable Task Manager task, first attempted after `authd.purge_delay` seconds (default `120`) and retried until it succeeds, so an Indexer outage delays a deletion rather than losing it. `DELETE /agents` therefore returns before the documents are gone; tooling that deletes an agent and immediately asserts on the Indexer has to wait. A deletion can now also be **refused** with the new `1766` when too many earlier ones are still pending — the agent is left untouched and the request can be retried once the backlog drains. Agent IDs are never reused, so the IDs handed out after a deletion may skip values.
- `<global><agents_disconnection_alert_time>` was removed, and a configuration still carrying it fails to start — `<global>` now accepts `<agents_disconnection_time>` alone. It delayed the agent-disconnection *alert* while a flapping agent still had a chance to come back, but alert emission to `analysisd` was already removed in 5.0, so it controlled only the timing of a debug log line, and its last consumer went with `wazuh-manager-monitord`. Agents are still marked `disconnected` after `<agents_disconnection_time>` with no delay, which is what this option never gated. `remoted`'s active-configuration report no longer includes the field.
- An internal option written with no value (`remoted.debug=`, or with only spaces) now refuses the daemon's start. It used to be read as `0`, which passed the range check on every option whose minimum is `0` and failed it on the rest, so the same unfinished edit either started the daemon with a value nobody chose or stopped it, depending on which option it was. An option that is absent still falls back to its default. Applies to every daemon, on the manager and on the agent, and to both `internal_options.conf` and `local_internal_options.conf`. ([#38549](https://github.com/wazuh/wazuh/issues/38549))
- The `wazuh-manager-monitord` daemon was removed, and its periodic work moved into the Task Manager inside `wazuh-modulesd`: the agent disconnection sweep, the disconnection log line, the retention deletion of long-disconnected agents (`monitord.delete_old_agents`) and both daily and size-based log rotation. Every option keeps its meaning, range and default, and no new `<task-manager>` configuration is introduced, but the manager's internal options **moved from the `monitord.` namespace to `wazuh_modules.manager_task_*`** (for example `monitord.rotate_log` → `wazuh_modules.manager_task_log_rotate`; the full table is in the manager configuration migration guide). An override left under the old name is silently ignored, so rename any you had set in `wazuh-manager-internal-options.conf`. Agents are unaffected and keep `monitord.*` for their own log rotation. Because these options have no XML element, the values a running manager resolved are reported by `GET /manager/configuration/wmodules/wmodules` under the `task-manager` module's `recurring_tasks` object. **The `monitor` component of the active-configuration endpoints is gone**, since it was served by monitord's own `getconfig` socket: `GET /manager/configuration/monitor/{global,internal}` and the `/cluster/{node_id}/...` equivalent now return `400`. It only ever returned monitord's own internal options, and the Task Manager exposes no `getconfig` endpoint, so there is no replacement request. Three behaviours also change: the disconnection sweep no longer runs on cluster workers (it did, despite the flag that was meant to prevent it, and a cluster stanza that fails to parse is now treated as "not the master" instead of silently as master); daily rotation now fires after a same-day restart, where the previous implementation re-seeded its day baseline on every start and so never rotated on a manager restarted daily; and size-based rotation is checked once a minute rather than once a second. Runs are now durable, retried and queryable per schedule instead of living in process memory. Tooling that lists manager daemons must drop `wazuh-manager-monitord`. See [Recurring manager tasks](modules/task_manager/schedules.md).
- `wazuh-authd` now enforces TLS 1.3 as the minimum protocol version for agent enrollment and rejects TLS 1.2 or older handshakes; the `auth.ssl_auto_negotiate` configuration option and the `-a` CLI flag were removed, and both the manager's `<auth><ciphers>` and the agent's `<enrollment><ssl_cipher>` now expect a TLS 1.3 ciphersuite list instead of an OpenSSL cipher-list string. The agent's `<enrollment><auto_method>` option was also removed. ([#38091](https://github.com/wazuh/wazuh/issues/38091))
- Syslog remote input (`remoted` `syslog` connection mode, port 514) was removed. ([#34729](https://github.com/wazuh/wazuh/issues/34729))
- Ruleset migration: the Engine replaces `analysisd` and its ruleset format — XML decoders are replaced by YAML decoders ([#29585](https://github.com/wazuh/wazuh/issues/29585)), and CDB lists are replaced by KVDB key-value databases ([#31053](https://github.com/wazuh/wazuh/issues/31053)).
- The Vulnerability Detector offline feed was removed. CVE data is now distributed through Wazuh CTI into the Wazuh Indexer, and the Manager downloads it from the Indexer. Air-gapped deployments must provide access to an Indexer whose CTI consumer has been populated; custom/offline feed sources are no longer supported. ([#34919](https://github.com/wazuh/wazuh/issues/34919)) ([#31906](https://github.com/wazuh/wazuh/issues/31906))
- Agent metadata fields in Vulnerability Detection events moved from `host.*` to `agent.*` in the Indexer; index templates were updated accordingly. Custom dashboards, queries, and integrations targeting the previous field paths must be updated. ([#30535](https://github.com/wazuh/wazuh/issues/30535))
- Threat-related fields were aligned under the `wazuh` namespace in the Engine enrichment; queries and dashboards referencing the previous threat field locations must be updated. ([#35885](https://github.com/wazuh/wazuh/issues/35885))
- The VirusTotal integration was removed along with `integratord`. Real-time VirusTotal lookups have no direct replacement; IOC-based enrichment is now handled inline by the Engine against the Wazuh IOC database. Existing `integratord`-based VirusTotal configurations no longer apply. ([#36326](https://github.com/wazuh/wazuh/issues/36326))
- Active Response was redesigned around the Wazuh Indexer Alerting/Notifications plugins (new `active_response` channel type): the manager `ar.conf` file and the `<active-response>` and `<command>` configuration blocks were removed ([#34663](https://github.com/wazuh/wazuh/issues/34663)), and the `PUT /active-response` API endpoint was removed ([#34783](https://github.com/wazuh/wazuh/issues/34783)). ([#34606](https://github.com/wazuh/wazuh/issues/34606))
- The server-side OpenSCAP module was removed; use SCA instead. ([#31028](https://github.com/wazuh/wazuh/issues/31028))
- Inventory-related API endpoints were removed ([#31299](https://github.com/wazuh/wazuh/issues/31299)), along with the legacy API security configuration endpoints ([#28425](https://github.com/wazuh/wazuh/issues/28425)).
- Legacy configuration surfaces, database schemas, and compatibility layers were removed in the server cleanup. ([#34608](https://github.com/wazuh/wazuh/issues/34608))
- Manager index names changed to align with the new CTI and engine index aliases. ([#35525](https://github.com/wazuh/wazuh/issues/35525))
- Rootcheck server-side simplification: the manager-side rootcheck database, synchronization path, and read-only API were removed; findings are now indexed through the standard alert pipeline. ([#31478](https://github.com/wazuh/wazuh/issues/31478))

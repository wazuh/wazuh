# Build External Dependencies

Wazuh 5.x does not build its external dependencies (curl, openssl, rocksdb, ...) on every build. Each library is built once per platform, published to a pool at `packages.wazuh.com/deps/pool/`, and downloaded by `make deps`. `src/deps.lock.mk` pins which pool entry each library uses.

```
dependencies.json ──deps.py lock──► src/deps.lock.mk ──make deps──► packages.wazuh.com/deps/pool/<ref>/
        │                                                              ▲
        └── PR ─► 5_builderpackage_externals.yml builds the missing refs ─┘ (publish, after approval)
```

Files:

- `packages/externals/dependencies.json`: the inventory, one entry per dependency.
- `src/deps.lock.mk`: the pinned refs, generated by `deps.py lock`. Never edit it.
- `packages/externals/deps.py`: the inventory and pool tool.
- `src/engine/tools/third-party-notices/`: the license notices and the README third-party table.

Workflows:

- `5_builderpackage_externals.yml`: builds, tests and publishes the missing refs.
- `5_codequality_externals.yml`: checks the inventory, the lock, the pool and `THIRD-PARTY-NOTICES` on pull requests.
- `5_codeanalysis_externals-vulns.yml`: daily vulnerability scan.

4.x branches are not covered here: they keep `DEPS_VERSION` and the numbered sets at `packages.wazuh.com/deps/<N>/`, see [4.x branches](#4x-branches).

Implementation details for whoever changes the scripts or the workflow are in [Maintainer notes](#maintainer-notes), at the end.

## Bump a dependency

1. Edit its entry in `dependencies.json`: `version`, `revision`, `url`, `upstream_sha256` (`curl -fsSL <url> | sha256sum`) and `patches` if they change. `cpython` must match `framework/.python-version`; `libbpf-bootstrap` must match `LIBBPF_TAG` in `packages/externals/ebpf/build_ebpf.sh`.
2. Regenerate and commit `dependencies.json`, `src/deps.lock.mk` and `README.md`:
   ```bash
   python3 packages/externals/deps.py check
   python3 packages/externals/deps.py lock
   python3 src/engine/tools/third-party-notices/generate.py readme --write README.md
   ```
3. Open the PR **in Draft**. The workflow builds only the refs the pool does not have (the library and the ones that link it), smoke-builds agent and manager against them, and waits for approval on `publish`. `pool-check` and the rest of the CI stay red until the refs are published.
4. A `deps-publish` reviewer approves `publish` (see [Approve a publication](#approve-a-publication)). `publish` uploads the refs and `verify` reads them back.
5. Re-run `5_codequality_externals.yml`: `pool-check` turns green and the check of `THIRD-PARTY-NOTICES` runs. If it fails, run `make deps` and regenerate the file, which reads the license files `make deps` leaves in `src/external`:
   ```bash
   make -C src deps TARGET=manager
   python3 src/engine/tools/third-party-notices/generate.py notices --artefact manager --external src/external -o THIRD-PARTY-NOTICES
   ```
6. Mark the PR ready for review and merge as usual.

A **new** dependency also needs its `# deps-entry <name>: begin/end` block in `src/external/CMakeLists.txt`, its name in `EXTERNAL_RES` (`src/Makefile`), and a component in `components.json` with `"dependency": "<name>"` and the path of its license file.

What catches a mistake:

| Mistake | What fails |
|---|---|
| Lock not regenerated | `deps.py lock --check` |
| README table not regenerated | the `deps.py` tests, and `generate.py readme --check` once ready |
| Wrong sha256 | the build leg, when it checks the download |
| Patch no longer applies | the build leg |
| Entry without a component in `components.json` | `deps.py check` |
| Merged before publishing | `deps.py pool-check` |
| `THIRD-PARTY-NOTICES` not regenerated | `generate.py check` in `5_codequality_externals.yml`, once the refs are published |

## Change how a dependency is built

Pick the smallest form that expresses the change:

| Form | Where | Used by |
|---|---|---|
| Build option | the library's block in `src/external/CMakeLists.txt` (`CMAKE_ARGS`, `CONFIGURE_COMMAND`, `BUILD_COMMAND`) | lua, libplist, libpcre2 |
| Overlay (a file of ours over the upstream tree) | `packages/externals/overlay/<dir>/`, and `"overlay": "<dir>"` in the entry | rpm, popt |
| Patch | `packages/externals/patches/<lib>/NNNN-<name>.patch`, listed in `patches`; header with `Why:`, `Upstream:` and `Remove when:` | RxCpp, rpm, procps, date |

Keep each library's code inside its own block: a change there rebuilds only that library and the ones that link it. A change outside the blocks rebuilds every compiled library. Every dependency builds from its upstream release; only `geo_db`, which is data, is a `snapshot`.

## Approve a publication

`publish` runs in the `deps-publish` environment. Approving it is a **deployment review**, not a code review: it lets that one job of that one run assume the AWS role that writes to `deps/pool/*`.

| | Pull request review | `deps-publish` approval |
|---|---|---|
| Approves | the code, for merging | one job of one run, at one commit |
| Where | Files changed > Review changes | the run page > **Review deployments** |
| Who | the reviewers branch protection requires | the environment reviewers (one is enough) |
| Self-approval | no | no: whoever triggered the run cannot |

The run executes the workflow files of the PR, so review the whole diff at that commit, workflows included, before approving. On the run page: **Review deployments**, tick `deps-publish`, **Approve and deploy**. **Reject** fails the run and uploads nothing. From the CLI:

```bash
ENV_ID=$(gh api repos/wazuh/wazuh/actions/runs/<run>/pending_deployments --jq '.[].environment.id')
gh api -X POST repos/wazuh/wazuh/actions/runs/<run>/pending_deployments \
  -F "environment_ids[]=$ENV_ID" -f state=approved -f comment="reviewed <sha>"
```

`publish` is skipped until the repository variable `DEPS_POOL_PUBLISH` is `true`.

## Build locally or offline

`make deps` downloads from `DEPS_POOL_URL` (default `https://packages.wazuh.com/deps/pool`). To use a local copy:

```bash
python3 packages/externals/deps.py mirror --dest /tmp/pool --target manager --platform linux/amd64
make -C src deps TARGET=manager DEPS_POOL_URL=file:///tmp/pool
```

`--local DIR` takes refs from a local pool tree first (for example the `pool-new` artifact of a run); `--without cpython` leaves entries out.

To build everything from sources instead of precompiled tarballs: `make deps EXTERNAL_SRC_ONLY=yes`. On the Linux agent it skips `libbpf-bootstrap`, which has no sources, so the agent runs without eBPF whodata. With `DEBUG=yes` the dependencies build in Debug (`-g -O0`); `EXTERNAL_SANITIZE=yes` also instruments them, which only C++ module tests can use (the C executables that link `libwazuhext` no longer link). Run `make clean-external` when switching between Release, Debug and a sanitizer. Pool artifacts are always Release and uninstrumented: `build_external.sh` refuses to run with `DEBUG`, `FSANITIZE`, `TSANITIZE` or `EXTERNAL_SANITIZE` set.

To reproduce a workflow leg: pull its image with `packages/externals/pull_builder_image.sh` and run `packages/externals/generate_external.sh --system rpm --architecture amd64 --target agent --tag <tag> --verbose`. `DEPS_BUILD="curl openssl"` builds only those and takes the rest from the pool. The output lands in `packages/output_externals/pool/`. `libbpf-bootstrap` builds on `ubuntu:24.04` with `libelf-dev zlib1g-dev`, clang 20 and the Zig version pinned in the script: `bash packages/externals/ebpf/build_ebpf.sh`.

## How it works

### Refs and the pool

A ref is `<name>/<version>-<key>`, for example `curl/8.20.0-30451bbdcc7d`. A published ref is never modified.

```
deps/pool/<name>/<version>-<key>/
├── manifest.json
├── sources/<name>.tar.gz              tree after subdir, overlay and patches
├── linux/{amd64,aarch64}/<name>.tar.gz
├── darwin/{amd64,aarch64}/<name>.tar.gz
└── windows/<name>.tar.gz
```

Header-only libraries, test frameworks and data (`built: false`) have `sources/` only; `binaries` limits the platforms that get a tarball. `libbpf-bootstrap` has no `sources/` and also ships `linux/{arm32,i386,ppc64le}/`. `cpython` ships its built tree under `sources/` and the interpreter under `linux/`.

`manifest.json` records the inventory entry, the full `inputs_hash`, the refs of its links, the sha256 of every file, the toolchain of each build leg, and the run and commit that built it.

### What changes a ref

The key is the first 12 hex digits of a sha256 over everything that decides the bytes of the entry (`deps.py key`; `deps.py key-paths` lists the paths, and the workflow path filters follow it):

| Input | Changes the ref of |
|---|---|
| The entry's content fields (version, revision, sha256, patches, overlay, subdir, targets, platforms, format, strip, built); not url, license, CPE or other metadata | that library and the ones that link it |
| Its patches and overlay files | that library and the ones that link it |
| Its block in `src/external/CMakeLists.txt` | that library and the ones that link it |
| The text outside the blocks, the `# deps-recipe` blocks of `src/CMakeLists.txt`, `src/Makefile` and `src/cmake/WazuhExternalFlags.cmake` | every compiled library |
| The `# deps-recipe` blocks of `build_external.sh`, `generate_external.sh`, `consolidate.sh` | every library except cpython and libbpf-bootstrap |
| A `# deps-entry <name>` block of those scripts | that library and the ones that link it |
| The macOS runners and Xcode version in `builder-images.json` | every library built on macOS |
| `framework/cpython/compile.sh`, `framework/cpython/custom/**`, `framework/requirements.txt`, `framework/.python-version`, the `# cpython-recipe` block of `src/Makefile` | cpython |
| `ebpf/build_ebpf.sh`, `src/syscheckd/src/ebpf/src/modern.bpf.c` | libbpf-bootstrap |
| `KEY_EPOCH` in `deps.py` | everything |

Whole-line `#` comments of those files are ignored, so a comment or header edit gives no new ref (`#!` lines, patches, overlays and C sources count as they are). The `# deps-recipe` blocks wrap only what reaches the external build; product settings around them (Wazuh include directories, SELinux, audit, jemalloc options) are left out, and so are the test, Debug and sanitizer options (`TEST`, `ENGINE_TEST`, `DEBUG`, `FSANITIZE`, `TSANITIZE`, `EXTERNAL_SANITIZE`, the Debug flags and the Debug branch of `WazuhExternalFlags.cmake`), since the pool is never built with them: `build_external.sh` clears them and fails if the configured cache has any of them. Header-only targets in `src/external/CMakeLists.txt` sit in the `# deps-entry` block of their `built: false` entry, which goes into no key. The plumbing of the pipeline scripts (logging, leg selection, argument handling, toolchain records, guards that only abort) is left out too. What one library needs from the pipeline scripts (the expat workaround of `dbus`, the Perl modules of `openssl`, the autotools of `libplist`, the `sqlite`, `cJSON` and `procps` fixes) goes in a `# deps-entry <name>` block there, whose name must be an inventory entry not built by its own script. Nothing checks where a new setting goes: one that changes how the dependencies compile must go inside a block. Linking is declared in `links` and must match the `DEPENDS` of the library's `ExternalProject_Add`; `deps.py check` fails when a block uses a library its `links` do not reach.

### The workflow

Runs on pull requests (drafts included) that touch the key paths or `packages/externals/**`, and by hand (`gh workflow run 5_builderpackage_externals.yml --ref <branch>`). Use **Re-run failed jobs** for a failed leg.

```
check ─► build-externals (7 legs) ─┐                                    ┌─► smoke-build (7) ───┐
  │                                ├─► consolidate ─► cpython (2) ─► pool ─┤                      ├─► publish ─► verify
  └────► build-ebpf ───────────────┘                                    └─► smoke-sources (2) ─┘
```

| Job | What it does |
|-----|--------------|
| `check` | `lock --check` and `plan`: which refs are missing. Nothing else runs if none is. |
| `build-externals` | One leg per system, arch and target, in the builder image `builder-images.json` names, with the tag of the `VERSION.json` version (macOS natively). Builds the missing libraries; the rest come from the pool. |
| `build-ebpf` | Builds `libbpf-bootstrap` for every Linux arch with clang 20 and Zig. |
| `consolidate` | Merges the legs into one pool tree and writes the manifests. |
| `cpython` | Builds the interpreter and its wheels against the other refs, for amd64 and arm64 (manager only). |
| `pool` | Packs every new ref into `pool-new`; later jobs check its sha256. |
| `smoke-build` | Builds agent and manager (Linux amd64/arm64, Windows, macOS) against the new refs. Fails if any dependency is recompiled, which means a tarball was packed at the wrong path. |
| `smoke-sources` | Builds agent and manager with every dependency from its sources, in Debug, so a source that no longer builds blocks `publish`. |
| `publish` | Needs approval. Checks every ref against the lock and its manifest, then `publish_pool.sh` uploads it. |
| `verify` | Reads every published file back through `packages.wazuh.com`. |

Build legs: agent on `rpm-amd64`, `rpm-arm64` (CentOS 6 image, glibc 2.12), `macos-intel64`, `macos-arm64` and `windows-i686` (MinGW); manager on `rpm-amd64` and `rpm-arm64` (CentOS 7, glibc 2.17). There are no deb legs and no macOS or Windows manager. Intermediate artifacts go to the CI internal S3 bucket.

`cpython` and `libbpf-bootstrap` are built by their own scripts (`framework/cpython/compile.sh`, `ebpf/build_ebpf.sh`). Like `build_external.sh` for the rest, both download the release tarball of their inventory `url` and check it against `upstream_sha256`. A wheel bump in `framework/requirements.txt` rebuilds only cpython.

### Publishing

`publish_pool.sh` uploads every file with `--if-none-match '*'` and `manifest.json` last, so a ref without its manifest is incomplete and the next run completes it. A ref already published with the same `inputs_hash` is skipped; with another one, or a file already there with other bytes, the run stops and names the ref to delete. Each publishing run also writes `deps/pool/_published/<run>-<attempt>.json` with the refs it published.

The AWS role must trust only the OIDC token of the `deps-publish` environment (`sub` = `repo:wazuh/wazuh:environment:deps-publish`): a role trusted by the repository or a branch would let any PR publish without approval. It can only read and write `deps/pool/*` and cannot delete. The bucket policy denies a write without `If-None-Match`, does not deny deletes, and the bucket is versioned.

The tarballs the build jobs hand to `pool` through the CI bucket are not sealed: `verify --lock` rejects any ref or `inputs_hash` the lock does not give, but not other bytes under a right ref.

To publish by hand: extract the `pool-new` artifact, run `deps.py verify --lock --local pool-new/pool --pool file://$PWD/pool-new/pool`, then `publish_pool.sh pool-new/pool <bucket>` and `deps.py verify --local pool-new/pool`.

### Orphan refs

A ref no branch uses stays in the pool. Every week the manager scan of internal-devel-requests runs `deps.py orphans`, which lists the refs that no maintained branch (`main` and `X.Y.Z` with a commit in the last 120 days), `v*` tag or open pull request has referenced for at least 30 days, with the `aws s3 rm` commands to remove them. It deletes nothing; an admin runs the commands by hand. Never delete `deps/pool/_published/`.

## Reference

### Pull request checks

`5_codequality_externals.yml` runs on pull requests (drafts included) that touch the key paths, `packages/externals/**`, `src/engine/tools/third-party-notices/**` or `THIRD-PARTY-NOTICES`:

1. The `deps.py` tests.
2. `deps.py check`: schema, links, pins, names against `make print-EXTERNAL_RES`, and a component in `components.json` for every entry.
3. `deps.py lock --check`.
4. `deps.py pool-check`: every ref of the lock is published with the inputs it was keyed on. This is what keeps a bump from merging before its refs exist.
5. `make deps TARGET=manager` from the pool, precompiled, and `generate.py check --external src/external`: the committed `THIRD-PARTY-NOTICES` must be the one the license files of those refs give. It runs only once `pool-check` passes.

### Daily vulnerability scan

`5_codeanalysis_externals-vulns.yml` runs every day at 08:00 UTC from the default branch. For every versioned branch with commits in the last 120 days it builds an SBOM of all its dependencies, agent and manager, plus the wheels of `framework/requirements.txt`, from `dependencies.json` (or, on 4.x, from the `manifest.json` of its set), scans it with Grype and uploads the results to code scanning as `externals-vulns-<branch>`. A branch with neither file is reported as not supported yet, without failing. internal-devel-requests posts the new alerts in a daily issue at 09:00 UTC and the weekly report reads them; verdicts on false positives live there, in `core_dependencies/cve_verdicts.json`. A CVE fixed in a later version is not a verdict: bump the dependency.

### Inventory fields

`deps.py check` is the schema. Entries are sorted by `name`.

| Field | Meaning |
|-------|---------|
| `name` | Name in `EXTERNAL_RES` and directory under `src/external/`. |
| `version` | Upstream release the sources match, checked by content (build files often carry a stale version). |
| `revision` | Exact upstream tag or commit. |
| `source` | `upstream`, or `snapshot` for a published file (only `geo_db`). |
| `url` | Download URL; placeholders `{version}`, `{version_us}`, `{version_dash}`, `{version_concat}`, `{revision}`. |
| `upstream_sha256` / `snapshot_sha256` | sha256 of the downloaded file. |
| `format`, `strip` | Archive format (`tar.gz`, `tar.bz2`, `tar.xz`, `zip`, `file`) and leading directories to strip. |
| `subdir`, `overlay`, `patches` | Applied in this order after extracting. See [Change how a dependency is built](#change-how-a-dependency-is-built). |
| `targets`, `platforms` | `agent`/`manager` and `linux`/`darwin`/`windows`, checked against `make print-EXTERNAL_RES`. |
| `built`, `binaries` | `built: false` for header-only, test and data entries; `binaries` limits the platforms with a tarball. |
| `links` | Entries this one links; their keys go into its key. |
| `cpe`, `purl`, `scan`, `reason` | Identifiers for the vulnerability scan; `scan: false` needs a `reason`. |
| `license`, `author`, `homepage` | SPDX license and metadata; with `version` they fill the README table, `THIRD-PARTY-NOTICES` and the SBOM. |
| `notes`, `prebuilt` | Informational. |

### deps.py commands

`python3 packages/externals/deps.py <command> --help` lists the options. `plan`, `pool-check`, `mirror` and `verify` read the pool; the rest work offline.

| Command | Purpose |
|---------|---------|
| `check` | Validate the inventory. |
| `lock [--check]` | Write `src/deps.lock.mk`, or fail if it is stale. |
| `key [NAME...]`, `key-paths` | Print refs and inputs hashes; the paths that go into the keys. |
| `plan` | Entries whose ref is not in the pool. |
| `pool-check` | Every ref of the lock is published with its inputs. |
| `mirror --dest DIR` | Lay out the refs a target needs. |
| `verify --local DIR [--lock]` | Check a local pool tree against what the pool serves (and against the lock). |
| `manifest --pool DIR` | Write the manifests of a pool tree. |
| `sbom` | CycloneDX SBOM of the inventory or of a 4.x set manifest. |
| `orphans` | List unused refs (see [Orphan refs](#orphan-refs)). |
| `flatten`, `builder-image` | Used by the build scripts. |

### 4.x branches

4.x keeps `DEPS_VERSION` in `src/Makefile` and the numbered sets at `packages.wazuh.com/deps/<N>/`; a bump there is a new set and a new `DEPS_VERSION`, as before. ## Maintainer notes

Details for whoever changes the build scripts, the workflow or `deps.py`. Each block is self-contained.

<details><summary>Key inputs in detail</summary>

- Content fields: `version`, `revision`, `source`, `upstream_sha256`, `snapshot_sha256`, `patches`, `overlay`, `subdir`, `targets`, `platforms`, `format`, `strip` and `built`. `url` is left out: a mirror serving the same sha256 gives the same bytes. `binaries` is not keyed; it only decides which platform tarballs a manifest must have.
- The values `deps.py flatten` hands `build_external.sh` for the entry, except the URL, are keyed too.
- Patch files are hashed as text (CRLF read as LF). Overlay files are hashed raw with their executable bit, because `build_external.sh` copies them as is: a checkout that converts line endings in `packages/externals/overlay/` computes other keys.
- Builders: the macOS runners and Xcode version, for an entry built on macOS. The Linux and Windows images are pulled by the tag of the branch version and stay out of the key: rebuilding an image from the same Dockerfile, which moves the tag, rebuilds nothing. When a builder image changes what it compiles with (compiler, base system), raise `KEY_EPOCH` in a pull request opened once the push to the branch has published the new image, so every ref is built with it.
- `cpython` takes the `libwazuhext` block of `src/external/CMakeLists.txt`. A block whose name is no inventory entry counts as outside text. The block of a `built: false` entry goes into no key. `deps.py lock` fails when a built library has no block.

</details>

<details><summary>Manifest contents and when it is not written</summary>

`manifest.json` holds the `inputs_hash`, the inventory entry, the refs of its links, the commit and run that built it, the sha256 of every file, the `toolchain` of each leg (compilers and tools installed on the fly, and the digest of the builder image the leg ran in). `cpython` also records its wheels and the sha256 of `framework/requirements.txt`. On a pull request `wazuh_commit` is the PR head: the jobs build its merge with the base branch, whose commit GitHub does not keep.

The run fails without writing a manifest if an entry has no `sources/`, lacks a tarball for a platform of `binaries` (default `platforms`) that the run built, has binaries with `built: false`, or, for `cpython`, ships wheels that differ between architectures or from `framework/requirements.txt`.

</details>

<details><summary>What make deps downloads</summary>

From `$(DEPS_POOL_URL)/<ref>/`: `sources/<name>.tar.gz` always, unless the precompiled tarball already extracted the tree, and `<os>/<arch>/<name>.tar.gz` unless `EXTERNAL_SRC_ONLY` is set. A missing platform tarball is not an error: CMake builds that dependency from source. A missing source tarball fails. Transient errors are retried; a 403 or 404 is not.

The precompiled rules never fail `make deps`. The generic rule prints `[!] Precompiled <dep> ...` when a tarball exists but cannot be used; a 403 or 404, which is how a platform without binaries looks, stays silent, and the cpython rule is silent in every case. That is why `smoke-build` fails on any recompiled dependency.

`deps.py mirror` copies only `sources/` and the given platform, checks every file against its manifest, accepts `agent`, `manager` and `winagent` as `--target`, and stops if the lock is stale.

A dependency is downloaded for the targets that compile it, with three exceptions downloaded more widely for their headers: bzip2 (every target), audit-userspace and procps (every Linux target, because the unit-test wrappers in `src/unit_tests/wrappers/externals/` include their headers), and the test frameworks (every target, because `make deps` does not get `TEST=1`).

</details>

<details><summary>Build legs and smoke jobs</summary>

- The manager image builds a few libraries the agent image cannot. Both Linux legs build the agent set, and `consolidate.sh` keeps the agent copy where both produced one, so the binaries run with glibc 2.12. A leg packs a platform tarball only for a library that produced a compiled file (`.a`, `.so`, `.lib`, `.dylib`). Sources are the same on every leg and the first copy is kept. `consolidate.sh` fails if a leg of the matrix left no tarball (`EXPECTED_LEGS`).
- Builder images are pulled by `pull_builder_image.sh` with the tag of the `VERSION.json` version, and tagged locally with the first 12 digits of their digest (`BUILDER_TAG`); the full digest goes to the toolchain of the leg (`BUILDER_IMAGE`). Artifacts in the CI bucket: `externals-<leg>-<target>`, `libbpf-bootstrap`, `externals-all`, `cpython-<arch>`, `pool-new`, `smoke-build-<target>-<arch>`, `smoke-sources-<target>-<arch>`.
- `smoke-build` lays out with `deps.py mirror --local` every ref the target needs: the new ones from `pool-new`, the rest from the pool. The macOS agent builds natively, prepared like the package job (`generate_wazuh_packages.sh -i`) with the runner's default Xcode, so a clash with the Xcode the legs pin shows up before publishing. The Windows leg catches host tools shipped under `windows/` (for example `flatc`) built against a newer glibc than the consumer image.
- `smoke-sources` builds in two phases, `make deps EXTERNAL_SRC_ONLY=yes` plus `make build-external`, then the product: the engine looks for the built abseil directory at configure time and data_provider's services module does not wait for dbus, so one pass does not work. It fails if the dependency phase consumed anything precompiled. `cpython` comes built from `sources/` and `libbpf-bootstrap` is skipped.

</details>

<details><summary>Publishing in detail</summary>

`publish` first runs `deps.py verify --lock --local pool-new/pool --pool file://...`: every ref must be the one `src/deps.lock.mk` pins at that commit, with the `inputs_hash` of `deps.py key`, and every file must match its manifest. `publish_pool.sh` then needs bash 4.4, python3, an AWS CLI with `put-object --if-none-match` and `s3:ListBucket` limited to `deps/pool/`. Only a missing `manifest.json` (`NoSuchKey`) counts as unpublished; any other read error stops the run. If a file exists with other bytes (builds are not byte-reproducible), the run stops: it did not test those bytes, and the error prints the command to delete the incomplete ref.

The record `deps/pool/_published/<run>-<attempt>.json`, written with `--if-none-match`, holds the run, the pull request (`PUBLISH_PULL_REQUEST`), the commit (`PUBLISH_COMMIT`), the date and every ref of the tree. Run by hand, without `GITHUB_RUN_ID`, no record is written.

</details>

<details><summary>Orphan listing rules</summary>

```bash
python3 packages/externals/deps.py orphans --repo <clone> [--open-pr-refs refs/pull/N/head ...] [--published-runs <run>-<attempt> ...] [--grace-days 30] [--bucket <bucket>]
```

It needs a full clone of wazuh/wazuh with every branch and tag. A ref is kept while the lock of a maintained branch tip, a `v*` tag or an open pull request names it. The refs the lock ever had come from its history in every branch, tag and pull request. The date a ref stopped being used is the latest committer date among the commits whose lock has it and the commits that drop it from their first parent's lock; for a branch that stops being maintained, never earlier than the day it left the 120-day window. A fast-forward to an old-dated commit lists the refs it drops before the grace has run.

`--published-runs` reads the `_published/` records of the runs whose `publish` succeeded, so refs a pull request published and no branch keeps (changed, force-pushed or closed) are candidates too. Without it they are not seen. It fails instead of listing on a shallow clone, an `origin` that is not wazuh/wazuh or does not fetch every branch, no maintained branch or lock, a malformed or repeated `DEP_REF_` line, a missing pull request ref, a run without its record, or an unreadable pool. When the pool serves none of the maintained branches' refs it prints `PENDING` and lists nothing. Values of older locks that are not pool refs are ignored. The bucket is versioned, so a removal adds a delete marker and can be undone.

</details>

<details><summary>Debug and sanitizer flags</summary>

`src/cmake/WazuhExternalFlags.cmake` computes `DEPS_BUILD_TYPE` and `DEPS_CFLAGS_LIST` (curl uses `--disable-optimize` in Debug). `FSANITIZE=yes` or `TSANITIZE=yes` instrument only the project's C++; `EXTERNAL_SANITIZE=yes` adds the dependencies. Windows legs, openssl, jemalloc, popt (its CMake recipe gets no arguments) and the dependencies with their own build scripts take none of these flags. `build_external.sh` calls make with these variables empty and without `MAKEFLAGS`, `CMAKE_OPTS` or `CMAKE_BUILD_TYPE` from the environment, and fails if the configured cache is Debug or instrumented.

</details>

<details><summary>Inventory field details</summary>

- `version`: when no release matches the sources (rapidjson, date), the closest earlier release; `geo_db` carries its date.
- `revision`: for procps, which has no tags for 3.2.x, the release tarball name; for `geo_db`, the CTI export it came from.
- `snapshot`: `deps.py check` requires it to point under `packages.wazuh.com/deps/`; never use one to carry a code change.
- `subdir`: a relative path without `..` (procps uses `proc`). `overlay`: must exist and hold at least one file. Patches are relative to the tree after `subdir` and applied with `git apply -p1`; each header needs `Why:`, `Upstream:` and `Remove when:` before the first `diff`.
- `links` must match the `DEPENDS` of the library's `ExternalProject_Add` (for cpython, the manager's `WAZUHEXT_WHOLE_LIBS`); no cycles.
- `cpe`: versionless CPE 2.3, a list of them, or `null` with `scan: false`. `purl`: `pkg:github/<owner>/<repo>@<revision>` or `pkg:generic/<name>@<version>`, with a `/` in the version percent-encoded.
- `{version_concat}` is sqlite's form (`3.51.1` to `3510100`).

</details>

# PoC: signed WPK identifiers (#38283)

Manager-side prototype of the proposal in
[#38283](https://github.com/wazuh/wazuh/issues/38283#issuecomment-5295713144). remoted replaces the
WPK filename in a `remote_upgrade` payload with a short signed identifier **shaped like a filename**,
so the validator the manager already has and every deployed agent accept it with no change.

**Not production code.** The key is a process-wide singleton that re-stats the config on use rather
than watching it; the cluster key is found by substring scan, not a real XML parse; the hard link is
created at delivery rather than where the package is fetched; there are no metrics; and the TTL is a
placeholder that must be measured.

## What it changes

| File | Change |
|---|---|
| `src/auth/wpkId.{hpp,cpp}` | New. HMAC-SHA256 sign/verify, HKDF from `<cluster><key>`, the `wpk1.….wpk` format. |
| `src/endpoints/downloadEndpoint.cpp` | Resolves a signed identifier before the ordinary name path. **No parser change** — the value arrives through the existing `wpk` form. |
| `src/control/controlHandler.cpp` | Signs the identifier into the delivered payload and hard-links the package under its task id. No gate. |
| `tools/poc38283_taskd.py` | Stand-in task manager, so a pending upgrade exists without modulesd. |
| `tools/poc38283_wpkid.py` | The scenario matrix. |

## Format

```
signed := subject[4] || exp[4] || task_id[16]
id     := "wpk1." + base64url( signed || HMAC-SHA256(K, "WAZUH-WPK-ID\n1\n" || signed)[:16] ) + ".wpk"
K      := HKDF-SHA256( <cluster><key>, "WAZUH-WPK-ID-v1" )
```

**63 characters** in practice. It carries no filename, so it is authenticated rather than encrypted:
the claims — task id, subject, expiry — are not sensitive on their own.

The suffix is the trick: `isValidWpkFilename()` wants `[A-Za-z0-9._-]`, no leading dot and a `.wpk`
ending, and this satisfies all three.

## Resolution

`/download` opens `var/upgrade/<task_id>.wpk`, a **hard link** to the package placed there when the
task was prepared. Not a symlink — `openRegularFile()` uses `O_NOFOLLOW` and would refuse one. The
task id is derived from shared inputs, so every node names its own copy identically and whichever
node answers redeems what another issued. No wazuh-db on the path.

## Running it

```bash
# A non-default cluster key, or the manager refuses to issue (by design).
#   <cluster>…<key>…</key></cluster>   in etc/wazuh-manager.conf

head -c 4194304 /dev/urandom > /var/wazuh-manager/var/upgrade/wazuh-agent_5.1.0-0_amd64_c21ecaa.deb.wpk
python3 poc38283_taskd.py --wpk-file wazuh-agent_5.1.0-0_amd64_c21ecaa.deb.wpk &
python3 poc38283_wpkid.py --wpk-file wazuh-agent_5.1.0-0_amd64_c21ecaa.deb.wpk
```

## Result

**23/23** on a manager built and installed from this branch (Ubuntu 24.04, remoted on
`https://127.0.0.1:1517`), plus two checks on the key condition run separately.

| Claim | Evidence |
|---|---|
| The identifier is a legal filename | 63 chars, satisfies the manager's grammar unmodified. |
| It carries no filename | The basename appears neither in it nor in its decoded bytes. |
| The payload shape is unchanged | Still exactly `wpk_file`, `wpk_sha1`, `installer`. |
| Resolution is a hard link | The package is linked under its task id, `nlink=2`, same inode, not a symlink. |
| Identity binding | Another agent presenting it gets 404; so does a tampered one. |
| Expiry, and reuse within it | Expired gets 404; a valid one serves repeatedly, which retry needs. |
| Cross-node / cross-implementation | One signed by an independent Python codec from the same cluster key verifies on the manager, and the reverse. One signed under a different key gets 404. |
| Failures are indistinguishable | Wrong subject, expired, tampered, unknown task, missing package — all 404. |
| Plain filenames still work | A byte-identical legacy request still serves; a bad name is still 400; an unknown resource type is still 400. |
| The prefix does not swallow real names | A file called `wpk1.notsigned.wpk` is still read as a name. |
| Refuses the documented default key | With `<cluster><key>` set to `fd3350b86d…`, the manager sends the real filename. |
| Picks up a key change while running | Restoring a real key resumes issuing with no restart. |

## Not covered

- **The drop-in claim against a real, installed 5.0.0 agent.** Established here by the value passing
  the manager's grammar and by reading the agent source — not by running one. The most important
  thing to prove before committing.
- The agent-side cleanup patch, and the `var/incoming` accumulation on agents that cannot receive it.
- A TTL derived from measurement.
- Placing the hard link where the package is actually fetched, rather than at delivery.
